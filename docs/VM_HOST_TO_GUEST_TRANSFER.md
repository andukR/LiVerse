# Перенос файлов с хоста в Windows VM через виртуальный дисковод

Этот способ мы уже использовали для LiVerse и похожих сборочных артефактов.
Он полезен, когда не хочется:

- включать сеть в гостевой Windows;
- использовать флешку;
- писать файл по гостевому агенту вручную;
- пересобирать дистрибутив только ради переноса одного файла.

Ниже описан вариант через ISO-образ и `virsh change-media`.

Если нужен готовый однокомандный вариант, используй:

```bash
tools/transfer_to_windows_vm.sh PATH
```

## Когда подходит

- нужно передать один файл или небольшую папку из Debian-хоста в Windows VM;
- гостевая Windows видит виртуальный CD-ROM;
- доступ к VM идёт через `libvirt`/`virsh`.

## Общая идея

1. На хосте готовим временную папку со всеми нужными файлами.
2. Собираем из неё ISO-образ.
3. Подключаем ISO к виртуальному CD-ROM через `virsh change-media`.
4. В гостевой Windows открываем новый диск и копируем/запускаем файлы.
5. После работы ISO извлекаем и при необходимости заменяем на новый.

## Пример для LiVerse

### 1. Подготовить папку со файлами

Например, если нужно передать готовый установщик:

```bash
mkdir -p /tmp/liverse-transfer
cp ~/Жүктемелер/LiVerse-Setup-1.2.0.exe /tmp/liverse-transfer/
```

Если нужен ещё и проверщик SHA-256, положите его туда же.

### 2. Собрать ISO-образ

```bash
xorriso -as mkisofs \
  -o /tmp/liverse-transfer.iso \
  -V LIVERSE_SOURCE \
  /tmp/liverse-transfer
```

Что важно:

- `-V LIVERSE_SOURCE` — метка тома, которую потом увидит Windows;
- в ISO лучше класть только то, что реально нужно в госте;
- для больших файлов ISO можно пересобирать заново, это нормально.

### 3. Узнать имя виртуального CD-ROM

Если не уверены, какой у VM диск для CD-ROM:

```bash
virsh -c qemu:///system domblklist win10 --details
```

В нашем случае для `win10` использовался `sdc`, но это лучше проверить ещё раз,
если конфигурация VM менялась.

### 4. Извлечь старый образ и вставить новый

Если VM уже запущена:

```bash
virsh -c qemu:///system change-media win10 sdc --eject --live --config --force
virsh -c qemu:///system change-media win10 sdc /tmp/liverse-transfer.iso --insert --live --config
```

Если VM выключена, можно использовать `--update --config` вместо live-вставки:

```bash
virsh -c qemu:///system change-media win10 sdc /tmp/liverse-transfer.iso --update --config
```

### 5. Что делать в гостевой Windows

- открыть новый CD-ROM;
- скопировать файл в обычную папку;
- при необходимости запустить установщик прямо с диска.

## Как это использовалось для LiVerse

Раньше мы уже делали именно так для исходников и служебных файлов:

- собирали ISO через `xorriso -as mkisofs`;
- подключали его в VM через `virsh -c qemu:///system change-media ...`;
- в Windows открывали диск `LIVERSE_SOURCE`;
- запускали `sync_to_workspace.cmd`, если нужен был перенос исходников.

## Практическая рекомендация

Если нужно просто передать новый `LiVerse-Setup-<version>.exe` в VM для проверки,
то этот способ удобнее, чем копировать файл по кускам через guest-agent:

- меньше ручной возни;
- не нужен интернет;
- не зависит от Windows-папок и прав гостевого пользователя;
- файл можно сразу открыть в VM как обычный CD-ROM.

## Обратное направление: Windows VM → Debian

ISO — образ диска только для чтения, поэтому забрать через него собранный в
Windows установщик нельзя. Для большого файла используем временно
перенаправленную в VM флешку и готовый скрипт.

Когда флешка подключена к Windows VM:

```bash
tools/transfer_windows_release_via_usb.sh to-usb 1.2.1
```

Скрипт копирует установщик, файл SHA-256, отчёт сборки и проверщик, а затем
сверяет хэш копии на флешке.

После безопасного возврата флешки в Debian:

```bash
tools/transfer_windows_release_via_usb.sh from-usb 1.2.1 /media/$USER/ANDREY
```

Файлы будут сохранены в `.windows-release/1.2.1`, а установщик будет повторно
проверен по SHA-256. Папка `.windows-release` локальная и не попадает в Git.
