# Загрузка новых проповедей «Родника» с YouTube

Эта инструкция пополняет локальную очередь проповедей для эмуляции LiVerse.
Аудио сохраняется в `.cache/liverse/replay_audio/`; исходные записи и уже
полученные файлы не изменяются.

## Что используется

- Канал «Родник»: `UCqO7ojmGKRrat4TN2GQW9eQ`.
- `yt-dlp` получает список роликов и скачивает аудио.
- `tools/replay_audio_files.py` — штатный загрузчик LiVerse: сохраняет аудио
  с правильным YouTube ID в имени файла.
- `tools/replay_rodnik_sermons.sh subtitles --run` скачивает только временные
  русские субтитры для уже загруженного аудио. Они нужны для нарезки коротких
  окон эмуляции, а не заменяют распознавание речи.

`youtube-transcript-api` полезен для текста уже известного ролика, но сам по
себе не выдаёт список видео канала. Для списка используем `yt-dlp`: он не
требует ключа YouTube Data API.

Нужна свежая версия `yt-dlp`. На этом компьютере загрузка проверена на
`2026.08.19`; устаревшая `2026.07.04` получала от YouTube ошибку `403`.

## 1. Сначала получить список без загрузки

В корне LiVerse:

```bash
cd /home/kriwoscheev/Projects/live_verse_vosk
.venv/bin/python -m yt_dlp --flat-playlist --playlist-end 50 \
  --print '%(id)s | %(title)s' \
  'https://www.youtube.com/channel/UCqO7ojmGKRrat4TN2GQW9eQ/videos'
```

`--flat-playlist` означает «получить только перечень»: аудио, видео и
субтитры этой командой не скачиваются.

До массовой загрузки нужно сравнить список с именами файлов в
`.cache/liverse/replay_audio/` и выбрать небольшую партию. Для первой партии
подходят три записи: это ограничивает сеть, место на диске и время
распознавания.

## 2. Скачать выбранную партию аудио

Подставьте только выбранные ссылки. Пример для трёх роликов:

```bash
cd /home/kriwoscheev/Projects/live_verse_vosk
.venv/bin/python tools/replay_audio_files.py \
  --download-url 'https://www.youtube.com/watch?v=VIDEO_ID_1' \
  --download-url 'https://www.youtube.com/watch?v=VIDEO_ID_2' \
  --download-url 'https://www.youtube.com/watch?v=VIDEO_ID_3'
```

Загрузчик выбирает аудиодорожку (`bestaudio`) и кладёт её в
`.cache/liverse/replay_audio/`. Если файл уже существует, его не следует
скачивать повторно: сначала проверьте YouTube ID в имени локального файла.

Если YouTube возвращает `403 Forbidden`, сначала обновите загрузчик:

```bash
.venv/bin/python -m pip install --upgrade 'yt-dlp==2026.8.19'
```

Лишь если это не помогло, можно добавить к команде
`--cookies-from-browser chrome`. Этот параметр даёт `yt-dlp` доступ к cookies
обычного профиля Chrome; используйте его только с явного разрешения владельца
профиля.

## 3. Докачать временные субтитры

```bash
cd /home/kriwoscheev/Projects/live_verse_vosk
tools/replay_rodnik_sermons.sh subtitles --run
```

Если у ролика нет русских ручных или автоматических субтитров, скрипт сообщит
об этом. Такой ролик не включается в обычный `next`, потому что пока из него
нельзя надёжно выбрать короткие временные окна.

## 4. Запустить обычную эмуляцию и разметку

```bash
cd /home/kriwoscheev/Projects/live_verse_vosk
tools/replay_rodnik_sermons.sh next
tools/replay_rodnik_sermons.sh review-slides --browser
```

`next` берёт до трёх ещё не обработанных воскресных записей с временными
субтитрами. После успешной разметки можно снова выполнить `next`. Если
локальная очередь закончилась, `next` сам найдёт на канале до трёх отсутствующих
записей, скачает их аудио и временные русские субтитры, затем продолжит
эмуляцию. Поэтому для обычной работы достаточно одной команды `next`.

## Объём и порядок работы

Сейчас в кэше около 3,2 ГБ на 63 записи: грубая оценка одной полной
проповеди — 50 МБ. Поэтому три записи обычно занимают порядка 150–250 МБ, а
очередь из сотен записей нужно загружать партиями, а не целиком. Перед каждой
новой большой партией сначала получить список и сверить свободное место.
