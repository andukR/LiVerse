# План следующих функций LiVerse

Этот документ фиксирует идеи, которые можно делать постепенно после базового
распознавания ссылок и показа слайдов.

## 1. Синтез речи для слабовидящих

Смысл: LiVerse не только показывает найденную цитату, но и может озвучить
ссылку или текст стиха.

Термин "синтез речи" означает превращение готового текста в голос. Это не
распознавание микрофона, а обратная задача: программа уже знает текст и читает
его вслух.

Минимальная версия:

1. Добавить настройку `--speak-found-reference` для desktop-версии.
2. При найденной ссылке произносить коротко: `Иоанн 3:16`.
3. Добавить настройку `--speak-first-verse`, чтобы читать первый стих найденной
   цитаты.
4. Сделать задержку или очередь, чтобы голос не перебивал новое распознавание.
5. Добавить кнопку включения/выключения в Android-версии.

Возможные движки:

- Linux: системный `espeak-ng`, RHVoice или Speech Dispatcher.
- Windows: встроенный SAPI-голос.
- Android: встроенный Android TextToSpeech.

Риск:

- Качество русского голоса зависит от установленного движка.
- На богослужении озвучка может мешать, поэтому по умолчанию она должна быть
  выключена.
- Для слабовидящих полезнее режим на личном телефоне, а не озвучка в зале.

## 2. Кнопка отправки цитат в WhatsApp-группу

Смысл: после проповеди оператор нажимает кнопку, и LiVerse готовит сообщение со
списком найденных ссылок и текстом стихов.

Термин "share intent" на Android означает стандартное окно "поделиться", через
которое пользователь сам выбирает WhatsApp, Telegram, почту и так далее.

Минимальная версия для Android:

1. Хранить историю найденных цитат за текущий запуск.
2. Добавить кнопку `Поделиться`.
3. Формировать текст:

   ```text
   Цитаты из проповеди:

   Иоанн 3:16
   Ибо так возлюбил Бог мир...

   Римлянам 8:1-2
   1. Итак нет ныне никакого осуждения...
   ```

4. Открывать стандартное Android-окно отправки.
5. Пользователь вручную выбирает WhatsApp-группу церкви и нажимает отправить.

Минимальная версия для desktop:

1. Использовать уже существующий список ссылок за сеанс.
2. Добавить экспорт в `.txt` или копирование в буфер обмена.
3. Оператор сам вставляет текст в WhatsApp Web.

Почему не стоит сразу делать автоматическую отправку:

- WhatsApp не даёт простой и стабильный официальный способ писать в группу без
  действий пользователя.
- Автоматизация WhatsApp Web хрупкая: меняется интерфейс, могут быть проблемы
  с безопасностью и аккаунтом.
- Надёжнее сначала делать "поделиться", где окончательную отправку подтверждает
  человек.

## 3. "Оглавление" для YouTube-проповеди

Смысл: получить список цитат с привязкой ко времени в видео. Это скорее не
оглавление, а таймкоды библейских цитат.

Пример результата:

```text
00:12:34 - Иоанн 3:16 - Ибо так возлюбил Бог мир...
00:18:05 - Римлянам 8:1-2 - 1. Итак нет ныне никакого осуждения...
00:42:10 - Псалтирь 22:1 - Господь - Пастырь мой...
```

Термин "таймкод" означает время внутри видео, например `00:12:34`.

### Насколько это сложно

Средняя сложность. Не запредельно трудно, потому что LiVerse уже умеет:

- распознавать речь через Vosk;
- находить библейские ссылки;
- хранить найденные ссылки в логе;
- показывать текст стиха.

Главная сложность не в поиске цитат, а в синхронизации времени.

Если LiVerse слушает живую проповедь во время записи, то его внутреннее время
начинается в момент запуска LiVerse. А YouTube-видео после монтажа может
начинаться иначе:

- перед проповедью добавили заставку;
- добавили музыку;
- вырезали паузы;
- начало богослужения и начало записи не совпали;
- файл мог быть перекодирован или смонтирован.

Из-за этого время `00:10:00` в логе LiVerse не обязательно равно `00:10:00` в
готовом YouTube-видео.

### Вариант A: простой ручной сдвиг

Подходит, если к видео обычно приклеивается одна фиксированная заставка, а
дальше проповедь не режется.

1. LiVerse сохраняет цитаты с временем от старта программы.
2. Пользователь указывает сдвиг, например:

   ```text
   видео начинается на 00:01:35 позже, чем LiVerse
   ```

3. Скрипт прибавляет или вычитает этот сдвиг.
4. Получается готовый список таймкодов.

Сложность: низкая.

Риск: если видео внутри вырезали или склеивали, один сдвиг уже не поможет.

### Вариант B: поиск цитат по готовому видео

Подходит, если нужно надёжно работать именно с финальным YouTube-видео.

1. Скачать аудио из YouTube-видео или взять локальный файл.
2. Прогнать аудио через Vosk уже после монтажа.
3. Искать цитаты по распознанному аудио.
4. Сохранять таймкоды прямо из финального аудио.

Сложность: средняя.

Плюс: синхронизация почти не нужна, потому что анализируется уже готовое видео.

Минус: обработка занимает время; нужен инструмент скачивания/извлечения аудио
и аккуратное хранение временных файлов.

Возможные инструменты:

- `yt-dlp` - скачать аудио с YouTube;
- `ffmpeg` - извлечь и привести звук к нужному формату;
- Vosk - распознать речь;
- общий `live_pipeline.py` - найти ссылки.

### Вариант C: полуавтоматическая привязка live-лога к видео

Подходит, если хочется использовать уже записанный live-лог LiVerse и не
перераспознавать весь YouTube-ролик.

1. LiVerse сохраняет не только ссылку, но и короткий кусок распознанной речи
   вокруг неё.
2. Из финального видео берётся распознанный текст с таймкодами.
3. Скрипт ищет совпадения между live-логом и финальным видео.
4. По найденным совпадениям вычисляется сдвиг или несколько сдвигов.

Сложность: высокая.

Плюс: может пережить небольшие вырезки.

Минус: алгоритм сложнее, больше ложных совпадений.

## Рекомендуемый порядок работ

1. История цитат в Android и desktop в одном формате.
2. Кнопка `Поделиться` в Android через стандартное окно отправки.
3. Экспорт цитат за сеанс в `.txt` на desktop.
4. Синтез речи на Android через встроенный TextToSpeech.
5. Синтез речи на desktop как отдельная опция, без включения по умолчанию.
6. Простой генератор таймкодов из live-лога с ручным сдвигом.
7. Экспорт "оглавления" в формате YouTube:

   ```text
   00:12:34 Иоанн 3:16 - Ибо так возлюбил Бог мир...
   ```

8. Отдельный режим анализа готового YouTube-видео через `yt-dlp`, `ffmpeg` и
   Vosk.
9. Только после этого рассматривать полуавтоматическую синхронизацию live-лога
   с уже смонтированным видео.

## Полуавтоматический режим по risk_score

Смысл: LiVerse показывает надёжные ссылки сразу, а сомнительные ссылки отдаёт
оператору на подтверждение. `risk_score` - это оценка риска ошибки, а не
математическая вероятность. Чем выше число, тем осторожнее надо быть.

Текущее состояние на 2026-07-09:

1. `risk_score` уже считается и пишется в новые live/replay-логи.
2. Аннотатор показывает `risk_score`, `risk_level` и причины риска.
3. По текущим replay-логам размечено 295 уникальных срабатываний. У 286
   размеченных случаев уже есть `risk_score`.
4. Добавлен анализ статистики в существующий скрипт:

   ```bash
   .venv/bin/python tools/analyze_vosk_probe_logs.py --log-dir .cache/liverse/vosk_probe
   ```

5. Текущая оценка риска стала полезнее, но включать полуавтоматический режим
   пока рано: даже осторожный порог `score >= 0.2` всё ещё пропускает 31
   ошибочный или сомнительный случай.

Предварительная статистика по размеченным случаям с `risk_score`:

```text
Всего с risk_score: 286
Верные ссылки: 166
Ошибки/сомнительные случаи: 120

low:    171
medium: 103
high:    12
```

Если считать `medium` и `high` как "нужно подтверждение оператора"
(`score >= 0.3`):

```text
Ошибочных/сомнительных поймано: 63
Ошибочных/сомнительных пропущено: 57
Верных ссылок ушло бы оператору: 52
Верных ссылок прошло бы автоматически: 114
```

Если поставить более осторожный порог `score >= 0.2`:

```text
Ошибочных/сомнительных поймано: 89
Ошибочных/сомнительных пропущено: 31
Верных ссылок ушло бы оператору: 104
Верных ссылок прошло бы автоматически: 62
```

Следующий шаг перед включением полуавтоматического режима:

1. Доработать признаки риска для оставшихся `low`-ошибок:
   - неоднозначная номерная книга, например `тимофею` без `первое/второе`;
   - восстановление диапазона через `missing_twenty_range_repair`;
   - слишком широкий диапазон из разорванного двузначного числа;
   - смешение `послание` и `книга пророка`;
   - подозрительные короткие ссылки из одного-двух чисел.
2. Снова посчитать статистику:

   ```bash
   .venv/bin/python tools/analyze_vosk_probe_logs.py --log-dir .cache/liverse/vosk_probe
   ```

3. Выбрать порог для полуавтоматического режима.
4. Только после этого добавить стартовую опцию:

   ```text
   Режим показа ссылок?
   Enter - автоматический
   Space - подтверждать все ссылки
   Tab - полуавтоматический
   ```

## Минимальный первый шаг для "оглавления"

Самый практичный первый шаг:

1. В live-лог добавить для каждой принятой цитаты:

   - время от старта LiVerse;
   - ссылку;
   - первый стих;
   - исходный распознанный текст.

2. Сделать команду:

   ```bash
   python tools/export_sermon_timestamps.py --log ... --offset 00:01:35
   ```

3. На выходе получить `.txt`:

   ```text
   00:03:12 Иоанн 3:16 - Ибо так возлюбил Бог мир...
   00:08:47 Римлянам 8:1 - Итак нет ныне никакого осуждения...
   ```

Этого достаточно, если заставка и музыка в начале обычно имеют фиксированную
длину, а внутри проповедь не режется.

## Открытые вопросы

1. Где будет основная кнопка `Поделиться`: Android, desktop или оба варианта?
2. Нужно ли отправлять весь текст диапазона или только первый стих?
3. Нужно ли включать цитаты, которые оператор отклонил?
4. Какой формат нужен для YouTube: просто текстовый список или описание,
   готовое для вставки под видео?
5. Обычно видео проповеди только получает заставку в начале или внутри тоже
   бывают вырезки?
