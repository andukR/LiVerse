# Release Notes LiVerse 1.2.10

## Что изменилось

- Исправлено продолжение списка ссылок: пауза между адресами определяется по
  времени аудио, когда ASR предоставляет временные метки, поэтому задержка
  обработки на медленном компьютере сама по себе не закрывает список.
- Парсер восстанавливает некоторые разорванные и усечённые ASR-формы перед
  маркером «стих», в том числе «восьм ой стих» и «десят стих», и разделяет
  склеенное «стихмарка» в адресном контексте.
- Если номер главы не распознан, LiVerse не подставляет главу 1 по номеру
  первого стиха диапазона. Компактная последовательность «книга — числа —
  следующая книга» связывает числа с первой книгой, а не с последующей.
- Исправлена запись решений очереди подтверждений в журнал; это сохраняет
  результаты оператора для последующего разбора.
- Добавлена необязательная диагностика времени этапов после ASR и загрузки CPU
  LiVerse. Подробные замеры выключены по умолчанию и записываются отдельно в
  `performance.jsonl`.

Подтверждённые примеры и ограничения описаны в
`docs/SMART_SLIDE_USER_GUIDE.md`.

## Разрешения Holyrics API Server

Новых разрешений Holyrics API в изменениях 1.2.10 не добавлено. После установки
всё равно проверьте подключение LiVerse к Holyrics и сохранённый набор
разрешений на церковном компьютере.

## Проверка перед использованием

1. Установить 1.2.10 поверх 1.2.9 и проверить сохранение настроек.
2. Проверить список из трёх адресов, произносимых подряд, включая усечённое
   числительное и короткую паузу между ASR-фрагментами.
3. Проверить неполный адрес без номера главы: он не должен открывать первую
   главу.
4. Проверить конструкцию «Иоанна 3:16, Лука…»: числа должны относиться к
   Иоанну, а не к следующему названию книги.
5. При проверке скорости включать подробные замеры только на диагностический
   запуск; обычная работа по умолчанию их не записывает.
