# Windows-дистрибутив и обновлятор LiVerse

Состояние зафиксировано 25 августа 2026 года перед началом работы над
обновлением готового Windows-дистрибутива.

## Что уже работает

- `make windows-vm-test` проверяет исходный код в Linux и Windows VM.
- `make windows-vm-engine` дополнительно собирает папку PyInstaller `onedir` с
  `LiVerse.exe`, `LiVerseEngine.exe` и необходимыми библиотеками и данными.
- `make windows-vm-installer` собирает установщик
  `LiVerse-Setup-<version>.exe`, выполняет чистую установку, проверяет GUI,
  движок и runtime-ресурсы, удаляет тестовую установку и проверяет сохранность
  пользовательских данных.
- Настройки и журналы Windows-версии находятся в `%LOCALAPPDATA%\LiVerse`, а
  не в каталоге программы. Переустановка программы поэтому не должна удалять
  настройки пользователя.
- Установщик LiVerse 1.1.0 был вручную проверен в Windows VM: ярлык, настройка,
  распознавание и показ стихов в HoLyrics работали.

## Что означает аналог `./gradlew installDebug`

Ближайшая существующая команда — `make windows-vm-installer`. Она полностью
собирает и проверяет установщик, но после автоматической проверки удаляет
тестовую установку. Отдельной команды, которая оставляет новую сборку
установленной и запускает её в видимом рабочем столе Windows, пока нет.

## Два разных механизма обновления

1. Установка LiVerse из исходников использует существующий Git-обновлятор. Он
   выполняет `git fetch`, обновляет рабочую копию и Python-зависимости. Этот
   механизм нужен разработческой/Linux-установке.
2. Готовый Windows-дистрибутив не должен требовать Git, Python, `pip` или
   виртуальное окружение. Для него нужен бинарный обновлятор: скачать новый
   `LiVerse-Setup-<version>.exe`, проверить файл и запустить установщик.

Эти механизмы нельзя смешивать. GUI должен выбирать бинарный обновлятор только
когда он запущен как упакованный Windows `.exe`.

## Реализованный контракт бинарного обновления

- Источник сведений: последний опубликованный выпуск GitHub Releases
  репозитория `andukR/LiVerse`.
- Номер версии: тег выпуска вида `v1.1.1`.
- Файл: ресурс выпуска с точным именем `LiVerse-Setup-1.1.1.exe`.
- Контрольная сумма: поле `digest` ресурса GitHub вида `sha256:<64 цифры>`.
- LiVerse сначала спрашивает разрешение пользователя, затем скачивает файл в
  `%LOCALAPPDATA%\LiVerse\updates`, сверяет размер и SHA-256 и только после
  успешной проверки запускает установщик.
- При отсутствии сети, выпуска, установщика или SHA-256 установленная версия
  продолжает работать без изменений.
- Обновлятор не обходит Windows SmartScreen и не изображает цифровую подпись.

Локальная реализация находится в `tools/release_updater.py`, а выбор между ней
и старым Git-обновлением — в `tools/liverse_gui.py`. Добавлены отдельные тесты
проверки версии, маршрута GUI, размера, SHA-256, атомарного скачивания и отказа
от повреждённого файла. После изменений полный набор содержит 245 тестов и
проходит на Linux.

`make windows-release VERSION=<номер> PREVIOUS_INSTALLER=<путь>` является
строгим вариантом сборки: он требует ветку `main`, чистое рабочее дерево,
совпадение указанного номера с `version.py` и установщик предыдущей версии.
После чистой установки команда также проверяет обновление поверх предыдущей
версии с сохранением пользовательских данных. Предыдущий установщик попадает
только на временный сборочный CD-образ, но не в Git и не в новый установщик.
Это защищает официальный выпуск, не запрещая промежуточные диагностические
сборки командой `make windows-vm-installer`.
