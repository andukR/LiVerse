# Release Notes LiVerse 1.2.12

Живой тест с чтением и временным ограничением CPU выполнен на Linux-ноутбуке
03.10.2026, сеанс `20261003_182057_885119`: 406,5 с речи, 51 непустая фраза,
49 замеров; подготовка решения до 0,63 с, очередь до 1 с без роста.
Итог анализатора — «Условно можно использовать под контролем оператора»;
оператор подтвердил пригодность для работы с оператором и разрешил выпуск.
Этот результат относится к ноутбуку с приблизительным ограничением ресурсов;
короткая проверка установленной Windows-версии на церковном ПК остаётся нужной.

- Повторные проверки одинакового текста используют сохранённый результат
  поиска названий книг; в памяти остаются последние 256 окон. На ноутбуке
  обработка всех 292 фраз записи 03.10 ускорилась в 3,82–3,86 раза, полные
  результаты совпали в обоих проходах. Это не замер новой Windows-сборки.
- Во вкладке «Журналы» добавлена кнопка «Проверить сеанс»: автономная проверка
  одного завершённого запуска, причины решения, задержки, очередь, ошибки
  и сохранение отчёта. Итоги: условный допуск, не рекомендуется, недостаточно
  данных. Правильность физического изображения подтверждает оператор.
- Во вкладке «Состояние» добавлена кнопка «Текст для тестирования». Отдельное
  окно с прокруткой показывает тот же текст для чтения, что и консольный тест:
  отдельный адрес, обычная речь, список из четырёх ссылок, Лука 15:11–24 с УПС
  и следующий адрес. Окно доступно без Интернета и позволяет подтверждать
  ссылки во время чтения. Настройки подготавливает оператор по инструкции
  в начале текста; повторное нажатие возвращает к открытому окну.
- Исправлена оценка ответа «быстрая презентация уже отсутствует» при завершении
  длинного отрывка: анализатор учитывает непосредственный подтверждённый возврат
  к нужному слайду плана. Неподтверждённый возврат и другие ошибки остаются
  причинами отказа; исходный ответ сохраняется в журнале и счётчике.
- В диагностику добавлены задержка от последнего аудиоблока до готового
  решения, связь замеров с фразами, штатная остановка и остаток очереди,
  модель процессора и ОС. Старые журналы анализируются с явными ограничениями.
- В существующем инструменте замеров добавлен живой консольный тест для
  Linux-ноутбука: проверяемое временное ограничение CPU, обычный интерфейс LV,
  текст для чтения, последующий анализ новых сеансов. Профиль приблизительный,
  не откалиброван под реальный церковный компьютер; Windows и Holyrics вне
  ограничений, память не моделируется.
- Ответы Holyrics проверяются как JSON-объекты: пустые, повреждённые ответы,
  HTML и вложенная ошибка больше не считаются успешным показом при HTTP 200.
  Обрывы соединения записываются в диагностику; неизвестный результат
  команды нельзя считать подтверждением изображения.
- Список ссылок без активного текстового плана закрывается по заданному
  времени показа; закрытие относится к временной быстрой презентации.

## Разрешения Holyrics API Server

Новых разрешений для анализатора и теста нет: анализатор не обращается к API.
Живой тест использует обычные разрешения режима плана, показа и возврата,
перечисленные в README. Перед использованием на церковном ПК проверить
действующие разрешения и настоящий показ списка/длинного отрывка.

## Проверка перед богослужением

1. Выполнить стандартные проверки сборки и установки Windows, включая
   обновление с предыдущей версии и сохранение операторских настроек.
2. Проверить кнопку «Проверить сеанс» в установленном LV без Интернета.
3. Открыть «Состояние» → «Текст для тестирования» и прочитать текст:
   адрес, обычная речь, список из четырёх
   ссылок, сразу длинный отрывок с УПС, следующий адрес; подтвердить изображение,
   отсутствие закрытия отрывка старым таймером и возврат к плану.
4. Остановить распознавание, проверить текущий сеанс, сохранить отчёт.
   Неполные данные не считать успешной проверкой. Допуск на ноутбуке относится
   к ноутбуку; для решения о воскресном запуске нужен тест церковного ПК.
