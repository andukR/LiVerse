# LiVerse 1.2.0: накопленные замечания перед выпуском

Записано 25 августа 2026 года. Этот список нужно завершить или явно перенести
в следующий выпуск до публикации Windows-версии 1.2.0.

## 1. Подтверждение с телефона и QR-код

- Убрать автоматическое открытие страницы подтверждения в браузере компьютера.
  На компьютере оператор уже может вручную управлять показом через HoLyrics.
- Сохранить подтверждение с телефона и параллельное локальное всплывающее окно.
- Не открывать QR-код во внешнем просмотрщике изображений, который растягивает
  его под размер экрана.
- Показывать QR-код в управляемом окне LiVerse фиксированного разумного размера,
  достаточного для уверенного сканирования с обычного расстояния.

Критерий: запуск телефонного режима не открывает браузер; QR помещается в
небольшое окно на ноутбуке и большом церковном экране и сканируется телефоном.

## 2. Синхронизация длинного диапазона и окон подтверждения

Когда длинный диапазон введён с телефона, распознавание последнего стиха
текущего слайда должно только переключить длинный диапазон дальше. Оно не
должно одновременно предлагать этот же стих как новую отдельную цитату во
всплывающем окне.

Критерий: после автоматического перехода на следующий слайд или возврата к
плану проповеди не остаётся вопроса о показе уже прочитанного последнего стиха;
случайное подтверждение не может прервать длинный диапазон.

## 3. Видимая работа микрофона

- Добавить в основное окно понятный индикатор поступления звука, например
  небольшой меняющийся столбик уровня.
- В диагностике снова показывать окончательно распознанные строки речи.
- Не превращать диагностику в поток всех промежуточных гипотез распознавателя.

Критерий: оператор без консоли видит отдельно, что звук поступает, и что именно
LiVerse окончательно распознал.

## 4. Вкладка «Помощь»

Минимальный текст:

> LiVerse настраивает и проверяет большую часть параметров автоматически. Если
> что-то не работает, программа подсказывает, что проверить. Первоначальную
> интеграцию с HoLyrics нужно выполнить вручную: включить API Server Local,
> создать token и разрешить необходимые команды.

Добавить пошаговый путь от главного окна HoLyrics до:

1. настроек;
2. API Server;
3. создания/копирования token;
4. списка разрешений и нужных флажков.

Снимки должны соответствовать реально используемой версии HoLyrics и не
содержать настоящий token.

## 5. Передача диагностических журналов

Нужна отдельная вкладка, где понятно объяснено:

- журнал содержит распознанные фразы, найденные ссылки, решения оператора,
  технические события и, если включена запись, звук микрофона;
- эти данные нужны для воспроизведения ошибок и улучшения распознавания;
- пользователь сам выбирает, какие сеансы и какие виды файлов отправлять;
- автоматическая отправка после завершения выключена по умолчанию и требует
  явного согласия.

Первый безопасный этап: выбрать сеансы, исключить секреты, показать состав и
создать один архив для ручной отправки. Автоматическая отправка в Google Drive
требует отдельно выбрать способ авторизации и папку назначения; token HoLyrics
никогда не должен попадать в архив.

## 6. Окно «LiVerse — итоги сеанса»

- Окно должно появляться после штатного завершения распознавания и в Linux, и
  в упакованной Windows-версии.
- Список ссылок должен прокручиваться.
- Кнопки «Поделиться в WhatsApp» и «Закрыть» должны иметь постоянную высоту и
  оставаться полностью видимыми при небольшом экране и Windows-масштабировании.
- Если ссылок нет, окно должно явно сообщить об этом либо не открываться по
  заранее зафиксированному правилу, а не исчезать из-за ошибки.

Критерий: на церковном Windows и в чистой VM окно появляется после штатной
остановки, обе кнопки видны полностью.

## Порядок реализации

1. Пункт 2 — ошибка, способная нарушить показ во время богослужения.
2. Пункт 6 — потеря итогов и дефект компоновки Windows.
3. Пункты 1 и 3 — небольшие улучшения работы оператора.
4. Пункт 4 — справка; текст можно добавить сразу, снимки — после получения
   безопасных изображений реального интерфейса HoLyrics.
5. Пункт 5 — отдельный этап: сначала локальный экспорт, затем добровольная
   автоматическая отправка.

## Состояние на 25 августа 2026 года

- Реализовано локально, требуется ручная проверка: пункты 1, 2, 3 и 6.
- В пункте 4 добавлены текстовая справка, путь к настройкам, список разрешений
  и три проверенных снимка реального HoLyrics. Фрагмент снимка разрешений с
  частично видимым token обрезается при показе.
- Для пункта 5 добавлены выбор сеансов и создание ZIP-архива. Перед упаковкой
  технические поля с token, password, secret и authorization скрываются;
  аудиозапись выключена по умолчанию. Автоматическая отправка и подключение
  Google Drive ещё не реализованы.
- Автоматические проверки: 253 теста; полный набор проходит.

Дополнительно телефонный пульт получил явную кнопку полноэкранного режима и
попытку удерживать экран включённым. Браузер показывает результат: штатное
удержание экрана может быть запрещено на обычном HTTP-адресе локальной сети.
В пульте также появились режим «Песни» и крупные кнопки следующего и
предыдущего слайда текущей презентации HoLyrics.
