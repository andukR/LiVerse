# Автоматический умный перелистыватель слайдов

## Назначение

Перелистыватель ведёт заранее известную последовательность текста по живой
речи. Первая область применения — чтение объявленного диапазона Библии. Та же
модель позднее может использоваться для компактных библейских слайдов и песен.

«Последовательность» здесь означает упорядоченный список элементов: отдельных
стихов, групп стихов на слайде либо строк и частей песни.

## Основные правила

1. Ручное действие оператора всегда важнее автоматического решения.
2. Новый уверенно распознанный полный адрес отменяет старую последовательность.
3. Во время чтения диапазона поиск сначала сужается до текущего и следующего
   элементов. Более дальний переход разрешается только по сильному совпадению.
4. Слабое совпадение допустимо только для ближайшего ожидаемого элемента и
   только при продолжающейся речи.
5. Время чтения может быть дополнительным доказательством, но никогда не
   является самостоятельной командой перелистнуть слайд.
6. Автоматическое движение назад запрещено.
7. Последний элемент завершает последовательность и возвращает прежнюю
   презентацию, если она была сохранена.

## Решения

- `keep` — оставить текущий слайд;
- `advance` — перейти на следующий после уверенного чтения границы слайда;
- `assisted_advance` — то же по слабому, но последовательному доказательству;
- `synchronize_forward` — догнать уверенно распознанный более поздний элемент;
- `complete` — завершить последовательность;
- `ignore` — не менять показ.

Слабое доказательство не является глобальным снижением порога. Оно принимается
только потому, что книга, диапазон и ближайшее ожидаемое место уже известны.

## Режимы показа

- «По одному стиху»: каждый стих является отдельным элементом.
- «Компактнее»: элементом является слайд с несколькими стихами; границей служит
  последний стих этого слайда.
- Песня, в будущем: элементом может быть строка, куплет или припев.

## Выход из последовательности

Нормальный выход происходит после последнего объявленного стиха. Если пастор
не дочитал диапазон, новый полный адрес или ручное возвращение к плану
проповеди отменяет старый режим. После разрыва последовательного чтения слабая
речь не должна притягиваться к старому диапазону.

## Этапы внедрения

1. Режим наблюдения: записывать предлагаемые решения, не перелистывая слайды.
2. Проверка на сохранённых проповедях и подбор безопасных границ слабого
   совпадения.
3. Включение перехода только к ближайшему элементу.
4. Строгая обработка нового полного адреса во время активного диапазона.
5. Экспериментальная оценка темпа чтения только как дополнительного признака.
6. Добавление песен отдельным адаптером без изменения общего ядра.

Режим наблюдения подключён как к живому запуску, так и к replay-эмуляции.
В replay он хранит отдельный воображаемый текущий слайд, переносит это
положение между соседними частями одного аудиоокна и пишет решения в события
`SMART_SLIDE_SHADOW`. Реальный результат эмуляции от этих решений не меняется.

Текстовый поиск для наблюдения сначала оценивает только текущий и следующий
элементы последовательности. Для них используется та же формула сходства с
библейским текстом, но допускается более слабое совпадение. Глобальный поиск по
всей Библии остаётся запасным способом догнать уверенно распознанное более
позднее место.

Совпадение с текущим стихом само по себе не означает, что стих дочитан: для
перехода должны быть услышаны как минимум два его последних слова. Если один
распознанный фрагмент содержит конец одного стиха, следующий стих и начало ещё
одного, последовательные локальные решения объединяются в один переход сразу к
актуальному слайду. Это не создаёт глобального поиска и не разрешает движение
назад.

В replay-режиме с Sherpa перелистыватель проверяет также развивающийся
промежуточный текст между паузами. Обычная обработка адресов по-прежнему
использует только окончательные результаты распознавания. Благодаря этому
предлагаемый слайд меняется у границы стиха, а не после завершения большого
звукового фрагмента.

## Первая проверка ограниченного поиска

На неизменной пачке `20260910_190517` в режиме «по одному стиху» первоначальный
глобальный механизм провёл диапазон Марк 1:21–34 только через 5 из 14 слайдов.
Ограниченный поиск увеличил результат до 10 слайдов. После локального снижения
минимума с трёх до двух значимых слов диапазон прошёл все 14 слайдов по порядку,
достиг последнего стиха и корректно завершился. Снижение действует только для
текущего или непосредственно следующего элемента известной последовательности;
глобальные правила поиска не изменены. Предложений перейти на другую книгу или
назад не было.

## Критерий включения

Новый механизм становится рабочим только если на отложенных записях уменьшает
пропуски и не увеличивает число неверных слайдов. До этого все новые решения
остаются только диагностическими записями в журнале.

## Операторские подсказки для длинного отрывка

Параметр `--long-range-operator-hints` (в окне LiVerse: «Подсказывать
оператору, не перелистывая автоматически») включает безопасный промежуточный
режим. Когда УПС видит достаточное основание для ближайшего или более позднего
слайда, пульт в браузере показывает текущий стих и предложенный стих. Оператор
выбирает «Оставить текущий» или «Перейти к предложенному».

Даже если распознавание уверенно услышало более поздний стих, предложенным
остаётся только ближайший следующий слайд: подсказка не скрывает промежуточные
стихи.

В этом режиме распознавание **не** отправляет `ActionGoToIndex` само. Перед
операторским переходом LiVerse сверяет текущий слайд с Holyrics: если оператор
успел перелистнуть его вручную, старая подсказка отклоняется как неактуальная.
Подсказки и решения записываются отдельно от обычных подтверждений цитат.

### Согласованный рабочий режим

Цель — не заставлять оператора непрерывно смотреть на экран и одновременно не
передавать сомнительное решение автоматике.

1. Слабое, но осмысленное совпадение с началом предполагаемого диапазона не
   переключает слайд. LiVerse подаёт короткий тон и голосом называет
   предполагаемый адрес.
2. Оператор отвечает только кнопками пульта: принять предложенное начало либо
   отклонить его. Голос оператора не используется, чтобы его ответ не смешался
   с речью пастора.
3. После принятия начала диапазон считается подтверждённым оператором. Внутри
   него УПС может последовательно перелистывать слайды сам, но только при
   достаточном совпадении с ближайшим ожидаемым стихом.
4. Если подсказка осталась без ответа, LiVerse ничего не показывает и не
   перелистывает автоматически.
5. Звуковые подсказки включаются вручную только в нужном браузере. Для
   Bluetooth-наушника оператор выбирает его устройством вывода звука в системе;
   LiVerse не подключает и не перенастраивает Bluetooth самостоятельно.

### План реализации

1. Добавить в существующий браузерный пульт включаемый звуковой канал: тон и
   короткую русскую фразу для уже существующих подсказок длинного диапазона.
   Готово.
2. Выделить безопасную категорию слабых совпадений, для которых вопрос
   оператору полезен, но автоматический показ ещё запрещён. Проверить её на
   размеченных replay-записях, начиная со случая Ефесянам 2:16–20. Первый
   вариант включается параметром `--text-operator-hints` (в окне LiVerse:
   «Спрашивать через пульт при слабом совпадении текста»): минимум 60 баллов,
   запас не менее 12 и не менее четырёх совпавших значимых слов. Он не
   показывает стих сам.
3. После ответа «Показать» создавать подтверждённую последовательность и
   разрешать УПС автоматические переходы только внутри неё.
4. Добавить ограничение частоты: не более одного повторного тихого напоминания
   через 10–15 секунд и никаких повторов после ответа или исчезновения
   подсказки.
5. Проверить на реальном компьютере вывод в Bluetooth-наушник, работу обеих
   кнопок и отсутствие автоматического перехода при отсутствии ответа.

## Разметка режима наблюдения

Решения `SMART_SLIDE_SHADOW` размечаются тем же аннотатором, но отдельной
командой `tools/replay_rodnik_sermons.sh review-slides`. Для каждого решения
показываются текущий и предложенный слайды, распознанная речь и соседние шаги
того же диапазона; доступно прослушивание обычного и расширенного окна.

Категории: верный переход, верное удержание текущего слайда, неверный переход,
пропущенный переход и недостаточно данных. Результаты сохраняются рядом с
журналом в `smart_slide_reviews.jsonl`. Они не попадают в
`trigger_cases.jsonl` и не используются для обучения наивного байесовского
алгоритма оценки риска.

### Визуальная разметка

Текстовый режим удобен для редкого разбора, но для массовой разметки следует
использовать локальный браузерный режим:

```bash
tools/replay_rodnik_sermons.sh review-slides --browser
```

Он не запускает распознавание заново и не управляет живыми слайдами. Он читает
сохранённые события обычного LiVerse, `SMART_SLIDE_SHADOW` и WAV-файл. После
одной кнопки «Запустить эмуляцию» звук идёт непрерывно. Обычная распознанная
ссылка меняет показанный отрывок, а внутри активного длинного диапазона экран
перелистывается по решениям УПС.

Пока всё правильно, оператор ничего не нажимает. При ошибке большая красная
кнопка или клавиша Enter останавливает звук и сохраняет ближайшее решение как
ошибочное. По умолчанию предложенный переход считается неверным, а решение
оставить слайд — пропущенным переходом; тип можно тут же уточнить. После
нажатия также сохраняется точное положение остановки внутри WAV. Рядом с
журналом создаётся отдельный `smart_slide_incidents.jsonl` с показанным
слайдом и ближайшими событиями распознавания. В окне появляется короткий
диагностический отчёт, который можно скопировать для разбора ошибки. После
остановки или во время просмотра кнопка «Назад 10 секунд» возвращает и звук,
и эмулируемое состояние слайда к выбранному моменту. После
завершения участка просмотренные и не отмеченные ошибкой решения сохраняются
как правильные. Непросмотренные решения, например после закрытия браузера, не
получают положительную метку. Все записи остаются в
`smart_slide_reviews.jsonl` и сразу доступны для экспорта НБА УПС.

## Отдельная НБА УПС

НБА (наивный байесовский алгоритм) УПС — отдельная простая статистическая
модель. Она отвечает только на вопрос: безопасен ли переход, уже предложенный
правилами УПС. Она не смешивается с НБА распознавания библейских адресов:
та модель отвечает на другой вопрос — верно ли распознана сама ссылка.

Экспорт размеченных решений:

```bash
.venv/bin/python tools/analyze_vosk_probe_logs.py \
  --log-dir .cache/liverse/rodnik_replay_batches \
  --asr-engine sherpa-0.54 \
  --export-smart-slide-training .cache/liverse/ml/smart_slide_training.csv
```

В CSV сохраняются все размеченные решения, включая верное удержание и
пропущенный переход. Для первой модели годятся только решения, где УПС
действительно предложил переход: `correct_transition` получает метку `0`
(переход безопасен), `wrong_transition` — `1` (нужно передать оператору).
Остальные строки остаются в таблице для следующей отдельной модели, которая
будет выбирать между «перейти» и «остаться».

Обучение пока создаёт и проверяет модель только по сохранённому CSV:

```bash
.venv/bin/python tools/analyze_vosk_probe_logs.py \
  --train-smart-slide-model .cache/liverse/ml/smart_slide_training.csv
```

Она не подключается к живому перелистыванию автоматически. До достаточного
количества разнородных проверенных записей модель служит только для оценки;
после проверки на отдельных, не участвовавших в обучении проповедях её можно
использовать как дополнительный предохранитель перед автоматическим переходом.
