# LiVerse

Текущая версия: **1.1.0**. История выпусков записана в
[`CHANGELOG.md`](CHANGELOG.md).

Проект для распознавания библейских адресов и текста цитат из живой русской
речи через Vosk с выводом результата в Holyrics.

## Зачем нужен LiVerse

LiVerse создаётся не ради замены оператора и не ради соревнования с его
скоростью. Во время проповеди оператору приходится постоянно ждать очередной
библейский адрес и как можно быстрее набирать его несколькими кликами. Из-за
этого внимание человека сосредоточено на технической реакции, а не на смысле
проповеди.

Задача LiVerse — снять эту постоянную нагрузку, но сохранить за человеком
контроль в сомнительных случаях. Оператор остаётся участником богослужения,
может слушать, размышлять вместе с собранием и вмешиваться только тогда, когда
автоматика не уверена или требуется особое решение.

Следующее естественное расширение этой идеи — автоматически показывать не
только названные библейские цитаты, но и заранее подготовленные строки плана
проповеди. Когда пастор произносит строку плана, LiVerse открывает
соответствующий текстовый слайд Holyrics; когда пастор называет библейский
адрес, LiVerse временно переключается на Библию, а затем возвращается к плану.

LiVerse также умеет найти стих, когда пастор не называет адрес, а произносит
сам текст цитаты. Эта функция по умолчанию отключена и включается одним из
текстовых или совместных режимов, описанных ниже.

## Что есть внутри

- `tools/vosk_grammar_probe.py` - основной скрипт.
- `tools/analyze_vosk_probe_logs.py` - разбор логов распознавания.
- `tools/replay_transcript.py` - проверка поиска цитат на сохранённом тексте
  Vosk без микрофона.
- `packages/bible_parser_core` - парсер библейских ссылок, общий live-pipeline
  и данные Библии. Модули `bible_text_search.py` и
  `text_citation_detector.py` отвечают за поиск произнесённого текста стиха и
  защиту от ложных переключений.

## Общий live-pipeline

`packages/bible_parser_core/src/bible_parser_core/live_pipeline.py` - общий
"мозг" LiVerse для desktop-версии и Android-версии. Pipeline здесь означает
цепочку обработки: взять очередной кусок текста от Vosk, помнить несколько
последних кусков, собрать возможные варианты полной ссылки, отфильтровать
старый контекст и вернуть найденную библейскую ссылку.

В этом модуле живут:

- генерация грамматики Vosk;
- буфер последних фраз Vosk;
- сборка кандидатов из нескольких фраз;
- защита от прилипания старой ссылки к новой;
- распознавание ссылок через `bible_parser_core.parser`.

`tools/vosk_grammar_probe.py` оставляет за собой desktop-части: микрофон,
логи, подтверждение оператором, web-экран и Holyrics. Android-приложение
использует тот же `live_pipeline.py` через Chaquopy, а микрофон и экран
оставляет Android-коду.

## Запуск

```bash
python3 tools/vosk_grammar_probe.py --text "неемия первая глава пятый стих"
```

Для микрофона:

```bash
python3 tools/vosk_grammar_probe.py
```

### Автоматический план проповеди

Перед запуском откройте в Holyrics текстовую презентацию с планом и покажите
слайд, с которого начинается проповедь. Затем запустите:

```bash
make liverse
```

LiVerse прочитает непустые слайды активной презентации, добавит их слова во
временный словарь Vosk и будет искать произнесённую строку среди текущего и
двух следующих слайдов. После совпадения поиск продолжается со следующего
слайда, поэтому отдельно повторённый библейский адрес обрабатывается обычным
парсером ссылок.

Если в строке плана есть адрес, сначала произнесите всю строку для показа
плана, а затем отдельно адрес для показа текста Библии. Обычные команды
`make liverse` и `run-liverse.cmd` уже включают распознавание текущей текстовой
презентации. При прямом запуске Python для этого нужен параметр
`--sermon-plan`.

### Распознавание цитаты по её тексту

Для этой функции нужен подготовленный файл `bible_index.db`. Это база SQLite —
обычный локальный файл с поисковым указателем слов Библии. Облачные службы и
подключение к интернету во время проповеди не используются. Проверенная база
из проекта `liverse_bible_indexer_v0.4.0` занимает около 134 МБ. Её можно один
раз скопировать в каталог `bible_index` внутри LiVerse:

```bash
mkdir -p bible_index
cp ../liverse_bible_indexer_v0.4.0/liverse_bible_indexer/bible_index/bible_index.db bible_index/
```

На Windows создайте рядом с `run-liverse.cmd` папку `bible_index` и положите в
неё тот же файл под именем `bible_index.db`. Если база находится в другом
месте, передайте путь параметром `--text-detection-db` либо добавьте в `.env`:

```env
LIVERSE_TEXT_DETECTION_DB=C:\путь\к\bible_index.db
```

При запуске режима распознавания цитат по тексту LiVerse заранее проверяет
наличие этой базы. Если файл не найден, до открытия микрофона выводится точный
ожидаемый путь и инструкция по копированию. Проверка особенно полезна после
первой установки на новый компьютер; обновление через GitHub сам файл базы не
скачивает.

Доступны четыре режима:

- `address_only` — только произнесённые адреса; это режим по умолчанию и
  прежнее поведение LiVerse.
- `text_only` — только текст цитаты; удобен для проверки без влияния адресного
  разборщика.
- `hybrid_auto` — адрес имеет приоритет, а уверенно найденный по тексту стих
  показывается автоматически.
- `hybrid_confirm` — адрес обрабатывается как обычно, а найденный по тексту
  стих сначала поступает в существующее окно или веб-пульт оператора.

Примеры запуска:

```bash
# Прежний режим, новая функция выключена
python3 tools/vosk_grammar_probe.py --citation-detection-mode address_only

# Проверка только поиска по тексту, без отправки в Holyrics
python3 tools/vosk_grammar_probe.py --citation-detection-mode text_only --slide-output none

# Совместный автоматический режим
python3 tools/vosk_grammar_probe.py --citation-detection-mode hybrid_auto --sermon-plan

# Совместный режим с подтверждением текстовых совпадений
python3 tools/vosk_grammar_probe.py --citation-detection-mode hybrid_confirm --sermon-plan --approval-ui popup
```

Постоянный выбор режима также можно записать в `.env`, например:

```env
LIVERSE_CITATION_DETECTION_MODE=hybrid_confirm
```

В совместных режимах Vosk работает со свободным словарём, то есть не
ограничивается небольшим списком слов из библейских адресов. Сначала LiVerse
проверяет явно произнесённый адрес, затем строку плана проповеди и только потом
ищет текст цитаты. После адреса текстовый поиск на несколько секунд
приостанавливается, чтобы один стих не был показан дважды.

Текстовый детектор хранит последние 35 распознанных слов и проверяет несколько
перекрывающихся отрезков длиной 5, 7, 10, 15 и 20 слов, а также весь очередной
окончательный фрагмент Vosk. Обычное совпадение должно независимо повториться
в двух соседних отрезках. Очень точная и характерная фраза может быть принята
сразу. `score` в журнале — сравнительная оценка похожести, а не вероятность;
`margin` — отрыв первого найденного стиха от второго кандидата.

Основные параметры настройки:

| Параметр | По умолчанию | Назначение |
|---|---:|---|
| `--text-min-words` | 5 | Не искать по слишком короткой фразе |
| `--text-buffer-words` | 35 | Число последних слов в памяти |
| `--text-window-sizes` | `5,7,10,15,20` | Длины проверяемых отрезков речи |
| `--text-candidate-limit` | 100 | Число стихов для подробного сравнения |
| `--text-result-limit` | 5 | Число лучших результатов поиска |
| `--text-acceptance-score` | 70 | Минимальная обычная оценка |
| `--text-immediate-score` | 90 | Оценка для возможного немедленного принятия |
| `--text-minimum-margin` | 12 | Минимальный отрыв от второго кандидата |
| `--text-minimum-matched-words` | 3 | Минимум совпавших содержательных слов |
| `--text-confirmations` | 2 | Сколько соседних отрезков должны подтвердить стих |
| `--text-confirmation-seconds` | 5 | Допустимое время между подтверждениями |
| `--text-duplicate-cooldown-seconds` | 30 | Запрет повторного показа того же результата |
| `--text-address-suppression-seconds` | 8 | Пауза текстового канала после явного адреса |
| `--text-search-interval-ms` | 300 | Минимальный промежуток между поисками |
| `--text-max-range-verses` | 2 | Искать один стих или пару соседних стихов |

Для проверки без микрофона подготовьте JSONL-файл, где каждая строка содержит
время в секундах и очередной окончательный результат Vosk:

```json
{"time": 0.0, "text": "ибо так"}
{"time": 0.8, "text": "возлюбил бог мир"}
```

Затем запустите:

```bash
python3 tools/replay_transcript.py sermon.jsonl --db bible_index/bible_index.db --output result.jsonl
```

Подробный файловый журнал содержит события `TEXT_QUERY`, `TEXT_CANDIDATE`,
`TEXT_PENDING`, `TEXT_ACCEPTED`, `TEXT_REJECTED` и `TEXT_SUPPRESSED`: в них
видны проверенная фраза, лучшие кандидаты, время поиска и причина решения.

### Проверка на Windows после обновления

Отдельный тестовый режим не нужен. Приветствие церкви следует создать в
Holyrics как отдельную презентацию типа `Текст` с одним непустым слайдом. Для
оформления можно назначить этому слайду собственную тему и фоновое изображение.

Порядок проверки перед богослужением:

1. Покажите на большом экране текстовый слайд приветствия.
2. Запустите LiVerse обычным ярлыком `LiVerse` на рабочем столе либо командой:

```bat
run-liverse.cmd
```

3. Убедитесь, что LiVerse сообщил о загрузке текущей текстовой презентации.
4. Прочитайте в микрофон строку приветствия с большого экрана.
5. Подтвердите найденный слайд обычным способом оператора.
6. Убедитесь, что LiVerse сообщил о слайде приветствия, а изображение на
   большом экране осталось прежним.

Эта проверка охватывает микрофон, Vosk, получение текущей презентации из
Holyrics, распознавание её текста и подтверждение оператора. После проверки
остановите LiVerse, откройте в Holyrics настоящий план проповеди и снова
запустите LiVerse обычным способом: слайды текущей текстовой презентации
загружаются только при запуске программы.

В обычном режиме консоль показывает приветствие и короткие статусы вроде
`слушаю`, `распознаю`, `найдена ссылка`. Подробный JSON выводится только с
флагом `--debug-console`; путь к JSONL-логу печатается только с
`--print-log-path`.

Для живого богослужения с подтверждением на телефоне:

```bash
python3 tools/vosk_grammar_probe.py --require-approval --slide-output both --open-operator-browser
```

При запуске будет напечатан адрес пульта подтверждения для телефона и адрес
большого web-экрана. Найденная ссылка попадёт в Holyrics только после кнопки
`Принять`. QR-код для телефона откроется отдельным окном через `eog` или
`xdg-open` на Linux, а на Windows - стандартным просмотрщиком изображений;
если это не нужно, добавьте `--no-open-operator-qr`. ASCII QR-код в консоль не
печатается; для старого консольного QR используйте `--print-operator-qr`.

При остановке `Ctrl+C` LiVerse показывает итоговое окно со списком
распознанных за сеанс ссылок и кнопкой `Поделиться в WhatsApp`. Если итоговое
окно не нужно, добавьте `--no-session-summary-popup`.

Если нужен только Holyrics без локального web-экрана:

```bash
python3 tools/vosk_grammar_probe.py --require-approval
```

Если оператор работает на том же компьютере, где запущен Holyrics, можно
использовать локальное всплывающее окно вместо web-пульта:

```bash
python3 tools/vosk_grammar_probe.py --require-approval --approval-ui popup
```

Окно показывает найденную ссылку крупным шрифтом. `Enter` отправляет цитату в
Holyrics, `Esc` или `Space` отклоняют её.

Если LiVerse распознал диапазон стихов, например `1 Иоанна 2:12-17`, в
окне подтверждения появляется дополнительная кнопка `Контекст`. Она означает:
показать найденный диапазон и запомнить его как главный отрывок проповеди.
После этого короткие ссылки без книги, например `семнадцатый стих второй
главы` или `двенадцатый стих`, LiVerse будет понимать как стихи внутри этого
запомненного отрывка. Если нажать обычную кнопку `Принять`, диапазон будет
показан как раньше, но главным отрывком не станет.

Отдельно запустить только web-экран:

```bash
python3 tools/slide_server.py --host 0.0.0.0 --port 8765
```

Большой экран: `http://127.0.0.1:8765/`

Пульт подтверждения: `http://127.0.0.1:8765/operator`

Звук каждого запуска микрофона автоматически пишется для диагностики:

```bash
.cache/liverse/vosk_probe/<run>/audio.wav
```

Каждое срабатывание LiVerse дополнительно пишется в:

```bash
.cache/liverse/vosk_probe/<run>/trigger_cases.jsonl
```

В каждой строке есть `timecode`, `window_start`, `window_end`, `vosk_text`,
`ref`, действие оператора и результат отправки. Это нужно для разбора ложных
срабатываний второго типа: можно открыть `audio.wav`, перейти к `timecode` и
решить, была ли ссылка названа на самом деле. Если аудио для отдельного запуска
не нужно, запустите с `--no-log-audio`.

Для разметки таких случаев используйте аннотатор:

```bash
python3 tools/review_trigger_cases.py
```

По умолчанию он берёт последнюю неразмеченную пачку replay-логов. Если replay
обработал несколько аудиофайлов, запускайте аннотатор именно без `--latest`,
потому что `--latest` означает только один самый новый `trigger_cases.jsonl`.
Аннотатор проигрывает нужный отрезок `audio.wav` через `ffplay` или `mpv` и
записывает выбранную категорию обратно в `trigger_cases.jsonl`. Категории
включают верную ссылку, неверно понятую ссылку, ложное срабатывание на пароним,
омоним, обычную речь, шум и непонятный случай.

Чтобы исправить уже размеченный случай, введите в аннотаторе `к N` или
`исправить N`, где `N` - номер случая в списке. После перехода выберите новую
категорию `1-7`; старая разметка будет перезаписана.

Если нужен вывод в Holyrics, задайте переменные окружения в `.env`:

```env
HOLYRICS_TOKEN=...
HOLYRICS_HOST=http://localhost
HOLYRICS_PORT=8091
HOLYRICS_THEME=
HOLYRICS_QUICK_MINUTES=0
```

`HOLYRICS_TOKEN` - это token из `Holyrics -> Settings -> API Server -> Manage permissions`.
Это не Web `API_KEY`. Для Local API token передаётся в URL.
`HOLYRICS_PORT=8091` - порт Holyrics API Server по умолчанию. Если в настройках
Holyrics API Server указан другой порт, запишите его в `.env`.
`HOLYRICS_THEME` - запасной параметр для запуска без плана проповеди. В обычном
рабочем режиме с `--sermon-plan` LiVerse не спрашивает тему: и отдельные стихи,
и длинные диапазоны получают тему текущей презентации плана проповеди. Если
план не используется, интерактивный запуск по-прежнему позволяет выбрать тему
из списка Holyrics.
`HOLYRICS_QUICK_MINUTES` - запасной параметр для неинтерактивного запуска.
Если значение больше `0`, LiVerse перед показом стиха запоминает текущую
текстовую презентацию Holyrics, показывает найденный стих, а через указанное
число минут закрывает стих и возвращает прежнюю текстовую презентацию на тот
же слайд. При обычном запуске LiVerse спрашивает время показа цитаты; Enter
означает `1` минуту, `0` выключает автоматическое закрытие. Число без буквы
означает секунды (`30`), а для минут добавляется русская `м` (`1м`, `0,5м`).
Старые обозначения `30s` и `1m` тоже принимаются, чтобы прежние инструкции не
перестали работать. В `.env` значение `HOLYRICS_QUICK_MINUTES` по-прежнему
задаётся в минутах.

В Holyrics API Server Local должны быть разрешены:

- `GetAPIServerInfo` - стартовая проверка, что Holyrics API Server доступен
- `GetBibleSettings` - получение текущей темы библейских слайдов
- `GetCurrentPresentation` - проверка текущей презентации Holyrics
- `ActionGoToIndex` - переход на распознанную строку плана проповеди или на
  следующий слайд читаемого длинного отрывка
- `CloseCurrentPresentation` - закрытие временного стиха перед возвратом к плану
- `ShowVerse`
- `ShowQuickPresentation` - для слайдов со списком ссылок и межглавных диапазонов
- `ShowText` - возврат к текстовой презентации плана проповеди
- `SetBibleSettings`
- `GetThemes` - необязательно; нужно только для ручного выбора темы при запуске

LiVerse также вызывает служебный запрос `GetTokenInfo`, чтобы проверить версию
Holyrics и список разрешений текущего token. Отдельно включать `GetTokenInfo`
в `Manage permissions` обычно не нужно. Эта проверка не заменяет первичную
настройку Holyrics: API Server должен быть включён, token должен быть создан и
записан в `.env`.

Если `HOLYRICS_TOKEN` ещё не записан, обычный запуск `make liverse` или запуск
ярлыком открывает мастер первоначальной настройки. Он показывает путь к
`API Server -> Manage permissions`, полный список галочек в столбце `Local`,
принимает скопированный token и порт, а затем сам создаёт `.env`. Token при
вводе не показывается на экране. Пустой ввод откладывает настройку до
следующего запуска. Чтобы снова открыть мастер при уже сохранённом token,
выберите `E` — «полная настройка» на стартовом экране LiVerse. В этом случае
Enter оставляет прежний token без изменений.

В полуавтоматическом режиме LiVerse может молча отклонять совсем ненадёжные
срабатывания, чтобы не перегружать оператора. Порог задаётся переменной:

```env
LIVERSE_RISK_AUTO_REJECT_THRESHOLD=0.9
```

`0.9` означает: если `risk_score` равен `0.9` или выше, ссылка попадёт в лог как
отклонённая, но не будет показана оператору и не уйдёт в Holyrics. `0` выключает
этот предохранитель.

Для обычных ссылок LiVerse больше не отправляет собственный текст Библии в
Holyrics через `ShowQuickPresentation`. Вместо этого он:

1. вычисляет Holyrics verse id в формате `BBCCCVVV`;
2. вызывает `SetBibleSettings` с `show_x_verses`: `1` для одного стиха или
   количеством стихов для диапазона;
3. вызывает `ShowVerse` с `{"id": "<verse_id>"}`.
   Если задано время показа цитаты, LiVerse перед этим вызывает
   `GetCurrentPresentation`, а после таймера вызывает
   `CloseCurrentPresentation` и восстанавливает текстовую презентацию через
   `ShowText`.

Например, `Иоанн 3:16` превращается в `43003016`.
`Иоанн 3:16-19` отправляется как `SetBibleSettings {"show_x_verses": 4}`,
затем `ShowVerse {"id": "43003016"}`.

Исключение — режим `--sermon-plan`. В нём `ShowVerse` заставляет Holyrics
переключаться из текстовой презентации в отдельный библейский модуль, из-за
чего между слайдами может появиться заставка или рабочий стол. Поэтому цитата
показывается как временная текстовая презентация через `ShowQuickPresentation`
с темой текущего слайда плана. По таймеру LiVerse напрямую вызывает `ShowText`
для возврата к плану, не закрывая показ отдельной командой. Благодаря этому
Holyrics применяет переход между двумя текстовыми слайдами без промежуточного
пустого кадра.

Формы вроде `Иоанн 3:16 до конца главы` или
`Евангелие от Иоанна третья глава с шестнадцатого стиха и до конца главы`
распознаются как диапазон от названного стиха до последнего стиха этой главы,
например `Иоанн 3:16-36`. Диапазон от пяти стихов считается длинным: LiVerse
не отдаёт его в обычный Bible module Holyrics по одному стиху, а делает
несколько текстовых слайдов через `ShowQuickPresentation`.

Межглавные диапазоны Holyrics Bible module не показывает как единый диапазон.
LiVerse обходит это ограничение тем же способом, через `ShowQuickPresentation`:

1. берёт текст стихов из локальной проверяемой Библии `sword_russinodal.json`;
2. берёт текущую Bible-тему из `GetBibleSettings`;
3. разбивает диапазон на несколько слайдов по разумному объёму текста;
4. отправляет текстовые слайды в Holyrics с той же темой.

Первый слайд содержит общий адрес всего диапазона, например
`Иоанн 3:16-4:2`. Следующие слайды адрес не повторяют. В текстовом или
совместном режиме LiVerse запоминает последний стих каждого слайда. Пока
пастор читает этот отрывок, распознавание новых адресов полностью отключено:
работает только поиск прочитанного текста, необходимый для определения конца
текущего слайда. Когда прочитан последний стих, LiVerse вызывает
`ActionGoToIndex` и открывает следующий слайд. После последнего стиха LiVerse
возвращает ранее показанную строку плана проповеди, а обычный поиск адресов
автоматически возобновляется. Показанный длинный диапазон также
становится текущим контекстом: последующие фразы вроде `двенадцатый стих`
или `с шестого по седьмой стих` разрешаются внутри этого диапазона без
повторного произнесения книги и главы. Обе границы короткого диапазона должны
входить в ранее объявленный большой отрывок.
Если план проповеди не был загружен, показ длинного отрывка просто завершается.
Если автоматическое распознавание конца слайда не сработало, оператор может
перейти дальше стрелкой вправо. При следующем распознанном фрагменте LiVerse
получит из Holyrics фактический номер слайда и продолжит с него. Двойной щелчок
по слайду плана проповеди завершает режим чтения длинного отрывка; после
сверки с Holyrics обычное распознавание возобновляется. Таймер
`HOLYRICS_QUICK_MINUTES` для длинных текстовых диапазонов не применяется,
чтобы LiVerse не закрывал чтение раньше времени.

Если LiVerse распознал не одну цитату, а список ссылок для самостоятельного
чтения, он показывает компактный текстовый слайд через `ShowQuickPresentation`,
например:

```text
Ссылки для чтения

Псалтирь 9:19
Псалтирь 38:8
Псалтирь 39:5
```

## Установка на Windows 10

Рекомендуемый способ для церковного компьютера - скрипт
`update-liverse-windows.ps1`. Он подходит и для первой установки, и для
обновления уже установленного LiVerse.

### Первая установка или обновление из консоли

Если браузер на старом компьютере сильно тормозит, можно поставить Git,
скачать последнюю версию LiVerse и создать виртуальное окружение одной
командой PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -Command "iwr https://raw.githubusercontent.com/andukR/LiVerse/main/bootstrap-windows.ps1 -UseBasicParsing | iex"
```

Старая команда с `bootstrap-windows.ps1` остаётся рабочей: теперь она скачивает
и запускает актуальный `update-liverse-windows.ps1`.

Скрипт делает следующее:

1. ищет `git`; если Git не найден, пробует поставить Git for Windows через
   `winget`, затем через официальный релиз Git for Windows на GitHub;
2. скачивает или обновляет репозиторий `https://github.com/andukR/LiVerse.git`
   из ветки `main`;
3. проверяет Python 3.10+; если Python не найден и доступен `winget`, пробует
   поставить Python 3.12;
4. сохраняет локальный `.env` с token Holyrics;
5. обновляет tracked-файлы проекта до последней версии GitHub;
6. пересоздаёт `.venv`, если виртуальное окружение повреждено;
7. устанавливает зависимости и сам LiVerse через рабочую для Windows 10
   последовательность `pip install -e . --no-build-isolation`;
8. создаёт ярлык `LiVerse` на рабочем столе.

По умолчанию проект лежит в `%USERPROFILE%\LiVerse`. Файл настроек с token
Holyrics лежит там же:

```powershell
notepad $HOME\LiVerse\.env
```

При обновлении `.env` не перезаписывается. Не добавляйте `.env` в Git: в нём
хранится локальный token Holyrics.

Запуск:

```powershell
cd $HOME\LiVerse
.\run-liverse.cmd
```

Если LiVerse уже установлен через Git, та же команда `bootstrap-windows.ps1`
обновит его до последней версии ветки `main`.

Если репозиторий уже скачан и нужно запустить новый скрипт из папки проекта:

```powershell
cd $HOME\LiVerse
powershell -NoProfile -ExecutionPolicy Bypass -File .\update-liverse-windows.ps1
```

Если PowerShell на компьютере работает нестабильно или его невозможно
обновить, используйте вариант без PowerShell:

```cmd
cd /d %USERPROFILE%\LiVerse
update-liverse-windows.cmd
```

Этот вариант использует обычный `cmd.exe`, `git`, `py/python` и `pip`.
Журнал обновления создаётся в той же папке `$HOME\LiVerse-update-logs`, только
с именем вида `liverse-update-cmd-XXXXX.log`.

Каждый запуск `update-liverse-windows.ps1` пишет журнал обновления в папку:

```powershell
$HOME\LiVerse-update-logs
```

Если обновление упало, пришлите последний файл вида
`liverse-update-YYYYMMDD-HHMMSS.log` из этой папки.

На церковном компьютере обычный запуск выполняется ярлыком `LiVerse` на рабочем
столе. Ярлык вызывает `run-liverse.cmd`, поэтому вручную вводить длинную команду
не нужно. Запуск без параметров включает тот же рабочий режим, что и
`make liverse`: интерактивный выбор полуавтоматического или автоматического
режима, вывод в Holyrics, QR-код и распознавание текущей текстовой презентации.
Сохранённые настройки подтверждения и времени показа используются повторно.
Тема не выбирается: LiVerse берёт её из текущей презентации плана проповеди.
Если передать свои параметры, они используются вместо настроек по умолчанию.

При обычном запуске LiVerse сначала проверяет публичную ветку `main` на GitHub.
Понятный номер выпуска хранится в одном общем файле версии, а Git-коммит служит
точным техническим обозначением сборки. Если на GitHub есть более новый коммит,
LiVerse показывает установленную и доступную версии:
`Enter` устанавливает обновление, `Space` продолжает запуск без обновления.
После успешного обновления программа автоматически перезапускается. Если
интернета нет, GitHub недоступен или Git не установлен, проверка пропускается и
LiVerse запускается как обычно. Файл `.env`, база `bible_index.db` и другие
неотслеживаемые Git пользовательские файлы не удаляются.

Если отслеживаемые файлы программы изменены локально, автоматическое обновление
не выполняется, чтобы не потерять работу. Проверка также пропускается в
дополнительной ветке разработчика. В этих случаях сначала нужно вручную решить,
что делать с изменениями или веткой.

### Номера версий и выпуски

LiVerse использует схему `MAJOR.MINOR.PATCH`, то есть `главная.новая.исправление`:

- `1.1.1` — исправления ошибок без новой крупной функции;
- `1.2.0` — новые совместимые возможности;
- `2.0.0` — несовместимое изменение способа работы или установки.

Единственный исходный номер находится в
`packages/bible_parser_core/src/bible_parser_core/version.py`. Команды
`python tools/vosk_grammar_probe.py --version` и
`python tools/slide_server.py --version`, метаданные Python-пакета и окно
обновления читают это же значение.

При подготовке выпуска нужно изменить этот номер, дополнить `CHANGELOG.md`,
прогнать тесты, создать один выпускной коммит и пометить его Git-тегом вида
`v1.1.0`. Обычные рабочие коммиты отдельно нумеровать не требуется: их точное
состояние всё равно определяется Git-коммитом.

Чтобы на церковном компьютере работали и адреса, и распознавание произнесённого
текста Библии, скопируйте `bible_index.db` в папку `bible_index` рядом с
`run-liverse.cmd` и один раз добавьте в `.env`:

```env
LIVERSE_CITATION_DETECTION_MODE=hybrid_confirm
```

После этого достаточно запускать ярлык `LiVerse`. При полной настройке время
вводится так: `30` — 30 секунд, `1м` — одна минута.

Для режима со всплывающим окном из PowerShell или Command Prompt:

```powershell
.\run-liverse.cmd --require-approval --approval-ui popup --sermon-plan
```

## Установка на Linux

1. Установите Python 3.10+ и `make`.
2. Если `python3 -m venv` не работает, поставьте пакет `python3-venv` или аналогичный для вашего дистрибутива.
3. Запустите:

```bash
./install-linux.sh
make liverse
```

`install-linux.sh` также создаёт desktop-ярлык `LiVerse` для текущего
пользователя. Файл ярлыка записывается в
`~/.local/share/applications/liverse.desktop`, а иконка - в
`~/.local/share/icons/hicolor/256x256/apps/liverse.png`. В меню приложений
Debian/GNOME после этого можно искать `LiVerse`; ярлык запускает тот же режим,
что и команда `make liverse`.

При первом запуске ярлыка LiVerse проведёт через настройку локального API
HoLyrics и сохранит token в локальном файле `.env`.

Если LiVerse уже установлен и нужно только создать или обновить ярлык:

```bash
./install-linux.sh --desktop-only
```

`make liverse` запускает режим богослужения с подтверждением через телефон,
выводом в Holyrics и QR-кодом в отдельном окне. При запуске LiVerse сначала
проверяет обновления, а затем спрашивает режим работы: `Enter` - полуавтомат,
`Space` - автомат, `E` - полная настройка, `Q` - выход.

Полуавтоматический режим означает: LiVerse показывает надёжные ссылки сразу,
а сомнительные отправляет оператору на подтверждение. Если включено
распознавание плана проповеди, уверенно услышанный пункт тоже переключается
автоматически, а неполное или сомнительное совпадение ждёт подтверждения.
Уверенно распознанный номер стиха или диапазон внутри ранее объявленного
контекстного отрывка также показывается сразу. Автоматический режим не
проверяет оценку риска и сразу отправляет найденные адреса и пункты плана в
Holyrics. При `LIVERSE_CITATION_DETECTION_MODE=hybrid_confirm` цитаты,
обнаруженные именно по произнесённому тексту Библии, в обоих режимах по-прежнему
требуют подтверждения оператора.

Остальные ответы сохраняются в `~/.config/liverse/settings.json`: способ
подтверждения, тема Holyrics и время показа цитаты. Поэтому обычный повторный
запуск требует только выбрать `Enter` или `Space`. Если нужно поменять тему,
время показа или способ подтверждения, нажмите `E` и пройдите полную
настройку. При полной настройке выбор режима старый: `Enter` - подтверждать
каждую ссылку, `Tab` - полуавтомат, `Space` - полностью автоматический режим.

Дополнительные параметры можно передать через `ARGS`, например:

Запуск с подтверждением:

```bash
make liverse ARGS="--require-approval --slide-output both --open-operator-browser"
```

Запуск сразу в полуавтоматическом режиме:

```bash
make liverse ARGS="--semi-auto-approval"
```

Если нужен полностью ручной набор параметров без настроек по умолчанию:

```bash
make liverse LIVERSE_ARGS= ARGS="--text 'Иоанн 3:16' --slide-output none"
```

После установки можно запускать и напрямую:

```bash
liverse
```

## Replay по записям проповедей

`Replay` здесь означает повторный прогон записи: LiVerse читает готовый
аудиофайл так, будто слушает микрофон на богослужении. Это нужно для массового
тестирования и сбора логов без присутствия на реальном служении.

Показать найденные аудиофайлы и примерную длительность:

```bash
.venv/bin/python tools/replay_audio_files.py
```

Запустить один найденный файл:

```bash
.venv/bin/python tools/replay_audio_files.py --limit 1 --run
```

Запустить конкретный файл:

```bash
.venv/bin/python tools/replay_audio_files.py --audio "/path/to/audio.wav" --run
```

Запустить все найденные файлы:

```bash
.venv/bin/python tools/replay_audio_files.py --run
```

Логи пишутся в тот же каталог, что и live-логи:

```bash
.cache/liverse/vosk_probe/<run>/
```

Внутри будут `session.json`, `events.jsonl`, `audio.wav` и, если были
срабатывания, `trigger_cases.jsonl`.

Если локальных аудиофайлов недостаточно, можно скачать новую запись с YouTube,
если установлен `yt-dlp`:

```bash
.venv/bin/python tools/replay_audio_files.py --download-url "https://www.youtube.com/watch?v=VIDEO_ID"
```

А чтобы сразу скачать и прогнать:

```bash
.venv/bin/python tools/replay_audio_files.py --download-url "https://www.youtube.com/watch?v=VIDEO_ID" --run
```

Если в соседних проектах уже есть файлы субтитров `.srt` или `.txt`, в имени
которых есть YouTube ID, можно превратить поиск новых записей в один pipeline:

```bash
.venv/bin/python tools/replay_audio_files.py --download-from-subtitles --limit 3 --run
```

Скрипт найдёт YouTube ID в названиях субтитров, пропустит уже скачанные
аудиофайлы, скачает недостающие записи в `.cache/liverse/replay_audio/` и
сразу прогонит через replay именно эту скачанную пачку. В конце он напечатает
статистику разметки: сколько срабатываний найдено в последней пачке, сколько
срабатываний уже размечено во всех логах, сколько осталось до целевого числа
аннотаций для оценки `risk_score`, и команду для разметки последней пачки:

```bash
.venv/bin/python tools/review_trigger_cases.py --latest-batch
```

Целевое число аннотаций по умолчанию - 200. Если нужно изменить ориентир:

```bash
.venv/bin/python tools/replay_audio_files.py --download-from-subtitles --limit 3 --run --target-annotations 300
```

Для эксперимента с машинным обучением можно выгрузить размеченные случаи в
CSV-таблицу:

```bash
.venv/bin/python tools/analyze_vosk_probe_logs.py --log-dir .cache/liverse/vosk_probe --export-training-data .cache/liverse/ml/training_cases.csv
```

В этой таблице `target_confirm=1` означает "случай нужно отдать оператору",
а `target_confirm=0` - "можно показывать автоматически".

После экспорта CSV можно обучить первую простую ML-модель без внешних
зависимостей:

```bash
.venv/bin/python tools/analyze_vosk_probe_logs.py --train-risk-model .cache/liverse/ml/training_cases.csv --model-output .cache/liverse/ml/risk_model.json --model-report .cache/liverse/ml/risk_model_report.json
```

Модель использует наивный байесовский классификатор. Это простой алгоритм
классификации, похожий по идее на старые фильтры "спам / не спам": он считает,
какие признаки чаще встречались у случаев "оператору" и "автоматически".

Для реальных live-тестов с микрофона разметку лучше начинать с последнего
живого запуска LiVerse:

```bash
.venv/bin/python tools/review_trigger_cases.py --latest-live
```

Если нужно перейти к последнему случаю в открытом логе, введите в аннотаторе:

```text
исправить 13
```

где `13` - номер случая на экране. После разметки live-логов снова выполните
экспорт CSV и обучение модели командами выше. В обучающем CSV есть поле
`run_source`: `live` для живых запусков LiVerse и `replay` для прогонов
YouTube-аудио.

Если нужно только посмотреть, что будет скачано и обработано, запустите без
`--run`:

```bash
.venv/bin/python tools/replay_audio_files.py --download-from-subtitles --limit 3
```

Для повторного прогона уже обработанных записей текущим кодом используйте
`--include-processed`. `--offset` нужен только для ручной проверки старых
записей пачками, когда вы намеренно добавили `--include-processed`.

```bash
.venv/bin/python tools/replay_audio_files.py --download-from-subtitles --limit 3 --offset 3 --run --include-processed
```
